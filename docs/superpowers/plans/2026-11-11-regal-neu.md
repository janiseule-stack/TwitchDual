# Regal neu – Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Die Regal-Ansicht in Home wird zur Live-Auswahl: Live-Favoriten stehen mit dem Cover nach vorne auf einem Ausstellbrett, alle anderen als Plattenrücken darunter. Ein Klick holt die Platte groß über das Regal (Titel, Spiel, Zuschauer). Die Rückseite zeigt eine große, scrollbare VOD-Liste, die beim Scrollen nachlädt. Das Regal ist auf jeder Fenstergröße ganz sichtbar.

**Architecture:** Die Belegung (Brett, Rücken-Fächer, Farben) und das VOD-Nachladen sind reine Funktionen in `renderer/lib/home-buehne.js`. Die Geometrie (Regal-Rechtecke, Skalierung mit Holzwand, Kartenmaße) steht in `renderer/lib/raum.js`. Die Darstellung baut `home-raum-dom.js`: Regal-Ebene mit Wand, Brett und Rücken, dazu die „Karte“ (große Platte vorne/hinten) in der bestehenden `.gross-platz`-Schicht. `home.js` ersetzt die Bühne (`createBuehne`, „vordere CD“) durch einen Zustand `herausgenommen`. Alle Bilder kommen aus PixelLab, Janis wählt. `tools/raum-bilder.py` bereitet sie auf, die gemessenen Orte stehen einmal in `tools/raum-quellen/regal.json`.

**Tech Stack:** Electron-Renderer (Vanilla JS, UMD-Libs), CSS, Node-Testrunner (`node --test`, `npm test`), Python/PIL `tools/raum-bilder.py`, PixelLab-MCP, `tools/home-groessen.js` (CDP-Screenshots).

**Spec:** `docs/superpowers/specs/2026-11-11-regal-neu-design.md` (Teil von `docs/superpowers/specs/2026-11-10-cozy-raum-design.md`).

## Review Focus

1. **Viele Live-Favoriten (z. B. 9) und nur 4 Brett-Plätze:** Auf dem Brett stehen die 4 mit den meisten Zuschauern, die übrigen 5 als Rücken in Favoriten-Farbe ganz vorne im Live-Fach. Gleichstand bleibt in Eingangsreihenfolge. Test in Task 2.
2. **Herausgenommene Platte geht beim 60-s-Refresh offline oder verschwindet (Abmelden):** Die Karte bleibt offen und zeigt „gerade offline gegangen“ ohne „Auflegen“. Abmelden legt sie zurück. Die Rückseite bleibt offen, solange der Login gleich bleibt. Test in Task 2 (`herausgenommenStand`) und statisch in Task 9.
3. **Schnelles Scrollen am Ende der VOD-Liste:** Es läuft höchstens eine Nachlade-Anfrage gleichzeitig. Eine späte Antwort für eine andere Platte wird verworfen. Doppelte VOD-IDs erscheinen nicht. Nach 100 VODs oder bei weniger VODs als angefragt ist Schluss. Der Scrollstand bleibt beim Anhängen. Tests in Task 2 (`vodLimit`, `vodsZusammen`) und Task 8 (statisch: kein `scrollTop = 0` beim Anhängen).
4. **Hochkantes oder sehr schmales Fenster (z. B. 700×900, 500×1000), angedocktes Video:** Brett, beide Rücken-Fächer und der Such-Zettel bleiben ganz sichtbar. Statt abzuschneiden gibt es oben und unten dunklen Rand. Test in Task 3.
5. **Suche mit fremdem Live-Treffer, Enter oder Klick:** Ein Klick lädt sofort (Ablauf mit Profilbild). Enter folgt weiter `enterZiel`. „vordere“ ist die herausgenommene Live-Platte, sonst der beste Live-Treffer, sonst `null`. Ein leeres Suchfeld plus Enter ohne Karte lädt nichts (bewusste Änderung, weil Home ohne vordere Platte startet). Statisch in Task 9.

**Interfaces:**
- Produces:
  - `HomeBuehne.regalBelegung({ abschnitte, plaetze, suche }) -> { brett: Kanal[], live: Eintrag[], unten: Eintrag[] }`. `abschnitte` = Ergebnis von `HomeListe.abschnitte(...).abschnitte`, `Eintrag = { kanal, art }` mit `art ∈ 'favorit'|'live'|'offline'|'twitch'`.

    - Dann der Abschnitt „live“, stabil nach `viewers` absteigend, `art 'live'`.
